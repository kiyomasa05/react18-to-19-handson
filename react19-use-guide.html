待つことを、render()の中へ。

React 19で追加された use は、PromiseやContextの値をレンダー中に「読む」ためのAPI。非同期UIをSuspenseと直結し、データ取得の考え方を変えます。

仕組みから理解する ↓ 先に注意点を見る

import { use } from 'react';

function Comments({ promise }) {
  // 値が返るまで、この部分を待機
  const comments = use(promise);

  return comments.map(comment =>
    <p key={comment.id}>
      {comment.text}
    </p>
  );
}

01 / OVERVIEW

use は何をするAPI？

ひと言でいうと、リソースの値をレンダー中に読み取るAPIです。React 19では、対象となるリソースはPromiseとContextです。

“

const value = use(resource)
値がすぐ読めれば返し、まだならその部分のレンダーを待たせる。データ取得の状態管理を、コンポーネントの外側にある Suspense / Error Boundary と協調させます。

P

Promiseを読む

解決済みなら値を返し、待機中ならコンポーネントをサスペンド。失敗したら最寄りのError Boundaryへ伝播します。

C

Contextを読む

useContextと似ていますが、条件分岐やループの中からでも呼べるのが大きな違いです。

名前はHook風。でもHookではない

useはコンポーネントまたはカスタムHookの中で呼びますが、通常のHooksとは異なり、条件分岐やループの中でも呼び出せます。ただしイベントハンドラーなど、レンダーの外で使うAPIではありません。

このデモはSuspenseとError Boundaryの役割を視覚化したものです。

基本形：Suspense + Error Boundary
import { Suspense, use } from 'react';
import { ErrorBoundary } from 'react-error-boundary';

function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);
  return comments.map(item => (
    <p key={item.id}>{item.text}</p>
  ));
}

export default function Page({ commentsPromise }) {
  return (
    <ErrorBoundary fallback={<p>読み込みに失敗しました</p>}>
      <Suspense fallback={<p>読み込み中…</p>}>
        <Comments commentsPromise={commentsPromise} />
      </Suspense>
    </ErrorBoundary>
  );
}
03 / MENTAL MODEL

useEffect と
何が違う？

どちらもデータ取得に関係しますが、開始するタイミングもUIの組み立て方も異なります。

観点use(promise)useEffect + state

ローディングSuspenseのfallbackに任せるisLoadingなどを自分で管理
エラーError Boundaryへ伝播try/catchしてstateへ保存
Promiseキャッシュ済みの同一インスタンスが必要Effect内で生成できる
向く場面Suspense対応のデータ層／Framework外部システムとの同期、手動fetch
宣言的：データを読む
function Profile({ userPromise }) {
  const user = use(userPromise);

  return <h1>{user.name}</h1>;
}
命令的：取得後にstateを更新
function Profile({ userId }) {
  const [user, setUser] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetchUser(userId).then(setUser).catch(setError);
  }, [userId]);

  if (error) return <p>失敗しました</p>;
  if (!user) return <p>読込中…</p>;
  return <h1>{user.name}</h1>;
}

use は useEffect の万能な置き換えではない

Effectは購読、DOM操作、外部ライブラリとの同期などに必要です。useが置き換えるのは「レンダーに必要なリソースを読む」という部分。役割を分けて考えましょう。

04 / CONTEXT

Contextを、
必要なときだけ読む。

use(context) は最寄りのProviderの値を返します。useContextと違い、早期returnの後や条件分岐の中で呼べます。

条件付きContext
import { use } from 'react';
import { ThemeContext } from './theme';

function Notice({ message }) {
  // 表示しないならContextを読む必要もない
  if (!message) return null;

  // ✅ 条件分岐の後でも呼べる
  const theme = use(ThemeContext);

  return <p className={theme}>{message}</p>;
}

05 / SERVER + CLIENT

Promiseは上流で作り、
下流で読む。

実務で重要なのは、useを呼ぶ場所よりPromiseを作る場所です。レンダー中に新規作成せず、Frameworkのキャッシュ、ルートローダー、Server Componentなどから渡します。

Server Component → Client Component
// Page.jsx — Server Component
import { Suspense } from 'react';
import Comments from './Comments';

export default function Page() {
  const commentsPromise = getComments();

  return (
    <Suspense fallback={<p>読み込み中…</p>}>
      <Comments commentsPromise={commentsPromise} />
    </Suspense>
  );
}

// Comments.jsx — Client Component
'use client';
import { use } from 'react';

export default function Comments({ commentsPromise }) {
  const comments = use(commentsPromise);
  return comments.map(/* ... */);
}

Server Componentでは async / await も有力

Server Component自身で値を使うだけなら、通常の await の方が自然なこともあります。useは、Promiseを子へ渡してストリーミングし、Suspense境界ごとに段階表示したい場面で特に効果を発揮します。

06 / PITFALLS

ここだけは、
外さない。

書き方は短くても、Promiseのライフサイクルまで短くなったわけではありません。

PITFALL 01

レンダー中にPromiseを作らない

use(fetch('/api')) は再レンダーごとに別のPromiseを作ります。同一インスタンスを返すキャッシュかFrameworkを使います。

PITFALL 02

try / catchで囲まない

useはtry-catchブロック内で呼べません。rejectはError Boundaryで受けるか、Promiseの.catchで代替値へ変換します。

PITFALL 03

Suspenseを上に置く

fallbackを表示する境界は、useを呼ぶコンポーネントより上に必要です。境界の粒度がローディング体験を決めます。

PITFALL 04

Server → Clientは直列化可能に

Server ComponentからClient Componentへ渡すPromiseの解決値は、Reactが転送できる直列化可能な値である必要があります。

違いは「Promiseの同一性」
// 🔴 fetch() は呼ぶたびに別のPromiseを作る
function Albums() {
  const albums = use(fetch('/api/albums'));
  // suspend → Reactが再レンダー → また別のPromise → suspend…
}

// ✅ URLごとにPromiseを1個だけ保存する
const albumCache = new Map();

function getAlbums(url) {
  if (!albumCache.has(url)) {
    // 初回だけPromiseを作り、Mapへ保存
    albumCache.set(
      url,
      fetch(url).then(response => response.json())
    );
  }

  // 再レンダーでも同じPromiseを返す
  return albumCache.get(url);
}

function Albums() {
  const albums = use(getAlbums('/api/albums'));
  // 同じPromiseが解決済みになり、albumsを取得できる
}

ポイントは関数名ではなく、返すPromiseが同じか

useが待機すると、Reactはそのコンポーネントを最初から再レンダーします。コンポーネント内で直接fetch()すると、再レンダーのたびに新しい待機中Promiseが作られます。外側のキャッシュから前回と同じPromiseを返せば、ReactはそのPromiseが解決したことを確認して続きを描画できます。実際のアプリでは、自作MapよりSuspense対応Frameworkやデータライブラリのキャッシュを優先してください。

  • Promiseは再レンダー間で同一か
  • 上位にSuspenseがあるか
  • 失敗時のError Boundaryがあるか
  • 境界の粒度はUXに合うか
  • 解決値は直列化可能か
  • Effectの置換が目的化していないか
07 / SUMMARY

use は、非同期処理を短くするAPIではない。

非同期の結果をレンダーの入力として読むことで、待機・成功・失敗をコンポーネントツリーの境界に接続するAPIです。

resource → use(resource) → Suspense / value / Error Boundary
